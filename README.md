# 顶子儿

一个 4×4 交叉点、黑白各 4 子的顶吃类棋戏。纯静态页面，无构建、无依赖，双击 `index.html` 即可玩。

## 规则

1. 棋盘 4×4 共 16 个交叉点，黑方占据首行、白方占据末行，黑先。
2. 每步沿横线或竖线把己方一子移到**相邻空位**，不能越子、不能跳吃。
3. **顶吃**：走子后，若你的两枚棋子在同一条线上**紧邻成对**，而这对棋子的一端紧挨着对方的棋子，对方那枚就被顶走。注意是"两子相连顶吃"，不是"两子夹一子"。
4. 只有本步走动的棋子参与形成的顶吃才结算；被顶走的只会是对方的子。
5. 一步同时形成两处顶吃时相互抵消，**一个都不吃**。
6. **满线免吃**：某条横线/竖线 4 格全满时，这条线上不产生吃子。
7. 任一方只剩 1 子即判负。

第 5、6 条属于民间玩法的分歧点，若要改动，只需改 `src/rules.js` 里的 `capturesFor`（抵消规则）与 `rowIsFull`/`colIsFull`（满线免吃），其余模块不必动。顶吃本身的形状判定集中在 `checkLine`。

## 目录

```
index.html          页面、样式、规则面板、模式切换
src/constants.js    棋子取值、棋盘尺寸、画布几何、模式枚举
src/rules.js        纯规则：走法、顶吃判定、威胁计算、胜负（无 DOM）
src/state.js        状态机：选中、走子、回合翻转、终局锁定
src/ai.js           贪心 AI：本步能吃 +1000，留下的威胁 +200/个，送给对方的吃子机会 -300/个
src/render.js       绘制与命中检测（像素 ⇄ 格子换算只在此处）
src/main.js         DOM 接线与回合循环
tests/              node:test 自测
assets/bg.png       400×400 的网格线背景图（线在 50/150/250/350）
```

`rules.js` / `state.js` / `ai.js` 用 UMD 壳导出：浏览器里挂到 `window.Dingzi`，Node 里可直接 `require`，因此不必引入打包器（`type="module"` 在 `file://` 下会被 CORS 拦住，故未采用）。

## 自测

```sh
node --test tests/rules.test.js tests/state.test.js
```

覆盖 `checkLine` 真值表（含"夹形不是顶吃"这条反向用例）、行/列顶吃、"与本步无关的顶吃不结算"、两处顶吃抵消、满线免吃、终局与输入锁定、AI 走法合法性与吃子倾向，以及一段 AI 对 AI 的整局推进检查——它断言一局里至少发生过吃子并且能分出胜负，把"谁都吃不到子"这种退化局面直接钉死。

## 已知边界

- 没有悔棋、没有和棋/无子可走判定。若某方被堵到无路可走，人机模式下会显示"X方无合法走法"并停住，双人模式下不会提示。
- 画布固定 400×400，未做移动端适配；命中检测每次点击重新量取 `getBoundingClientRect`，因此滚动与浏览器缩放不会导致点击错位。

## 后记

原实现是大学时的作业，`is_game_over` 里两个反向的错误相互抵消，播报的胜者碰巧是对的；`<canvas />` 的自闭合写法把后面的状态行吞成了 canvas 的 fallback content，导致提示全程不可见。这些坑现在都由 `tests/` 兜住。

吃子规则容易被误读成"两子夹一子"：原始 `checkLine` 命中后返回的是 `2` 或 `0`，`removeChessEat` 移除的是**窗口端点**那枚，即 `[己,己,敌]` 顶掉端点——游戏名字里的"顶"就是这个动作。改成夹形判定后照样能跑，但一局下来谁也吃不到子。
